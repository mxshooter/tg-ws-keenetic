# Cloudflare-прокси

Для недоступных дата-центров можно использовать альтернативный бесплатный
способ подключения — проксирование через Cloudflare. **Для работы нужен только
домен.** В прошивке есть домен по умолчанию, но его можно (и желательно)
заменить на свой.

Прокси возвращает доступ к тому, что раньше не загружалось (реакции, некоторые
стикеры). Если на аккаунте без Premium не загружаются фото/видео, оставьте в
блоке «Маршруты к ЦОД» только `4: 149.154.167.220`. Если CF-прокси работает,
медиа снова начнёт загружаться.

## Зачем мне настраивать свой домен?

Cloudflare имеет лимиты на одновременное количество WS-подключений. Домен по
умолчанию может перестать работать в любой момент.

## Настройка своего домена

1. Добавьте свой домен в Cloudflare (либо купив его напрямую у Cloudflare,
   либо изменив NS-серверы:
   https://developers.cloudflare.com/dns/zone-setups/full-setup/setup/).
   Подойдёт любой домен.

2. В `SSL/TLS` → `Overview` выставьте режим **Flexible**.

3. В `DNS` → `Records` добавьте следующие `A`-записи через `+ Add Record`:

   | Name     | IPv4              |
   |----------|-------------------|
   | `kws1`   | `149.154.175.50`  |
   | `kws2`   | `149.154.167.51`  |
   | `kws3`   | `149.154.175.100` |
   | `kws4`   | `149.154.167.91`  |
   | `kws5`   | `149.154.171.5`   |
   | `kws203` | `91.105.192.100`  |

4. **Добавьте домен в [zapret](https://github.com/Flowseal/zapret-discord-youtube/)
   или в любое другое ПО, так как подсеть Cloudflare может быть заблокирована
   (например, в России).**

5. В веб-интерфейсе роутера → **«Fake TLS & Cloudflare fallback»** →
   **«Пользовательские CF-домены»** укажите свой домен. Можно несколько через
   запятую:

   ```
   my.example.com, backup.example.com
   ```

   Или в `config.json`:

   ```json
   "cfproxy_user_domains": ["my.example.com", "backup.example.com"]
   ```

   Несколько доменов полезны, когда один упирается в лимиты Cloudflare:
   прокси пробует их по очереди и запоминает рабочий для каждого DC.

Если TLS-подключение к домену (порт 443) не отвечает, прокси автоматически
пробует тот же домен по HTTP (порт 80) и запоминает рабочий режим. Это
помогает, когда провайдер режет 443 до Cloudflare, но 80 работает. Домен,
на котором истёк таймаут, пропускается в этом режиме на 30 секунд. Если
нужно всегда ходить по HTTP, включите `disable_secure`.

## Мультиплексирование медиа через HTTP/2

Мультиплексирование включено по умолчанию (`cfproxy_h2_media: true`).
Медиа-соединения используют `/api` вместо `/apiws` через одно общее
TCP/TLS-соединение до Cloudflare для каждого DC и домена. Основные соединения
и тестовые DC продолжают использовать WS.

Чтобы отключить мультиплексирование, снимите галочку
**«HTTP/2 мультиплексирование медиа»** в том же блоке или задайте
`"cfproxy_h2_media": false` в `config.json`. Для самого HTTP/2 на роутере нужны
`httpx` и `h2`; без них прокси автоматически работает через WS.
